# HourLog 1.2.1 maintenance review

This review identified five corrections now included in HourLog **1.2.1 / code 4**, based on the published 1.2.0 source. The review was first validated locally; publication uses the original signing certificate for update continuity.

## Corrections

1. **Background lock deadline:** finishing PIN/password authentication or a credential change after the app entered the background previously cleared its background timer. The controller now preserves the original deadline, immediately keeps the app locked when the deadline has expired, and serializes session changes between the UI and credential-processing threads. A normal foreground unlock and Android system credential confirmation still work.
2. **Reminder after a spring DST gap:** an expired Sunday 02:30 reminder adjusted to 03:30 could carry that adjustment into the following week. Each occurrence is now resolved from its own date and the chosen wall time.
3. **Currency precision:** the app display and weekly CSV previously used the locale's default/two decimal places even when another currency was selected. Currency fraction digits now apply consistently to display, PDF and weekly CSV totals, with half-up rounding; tests cover JPY and KWD. Stored entries, rates and unrounded calculations are unchanged.
4. **Draft preferences:** appearance, hours format and default break choices now survive Activity recreation and a lock/unlock cycle. The reminder time and export-range dialogs also remain open across recreation.
5. **Settings navigation:** Android Back closes settings and returns to the current app screen.

The README's linked Obtainium mention and exact human/Codex credit remain present. No database schema or backup-format migration is introduced.
